# Milestone 2 acceptance checklist

Milestone 2 is an honest development-only single-node database. The gateway
is runnable, but it does not make distributed or transactional claims.

- [x] Pebble is pinned to commit `abab24a50ec83672322ca925a212eb33634615e6`.
- [x] Canonical tuple keys identify sequence metadata, immutable row versions,
  and current heads.
- [x] Row and sequence records have explicit versioned binary layouts and
  checksums; corrupt records fail explicitly.
- [x] A synchronized writer atomically commits sequence, history, version
  index, and head with `pebble.Sync`; reads copy values before closing Pebble
  handles.
- [x] UUIDv7 versions are unique across all immutable history, including after
  restart; duplicate generator output is bounded and rejected without a
  sequence advance.
- [x] Storage independently enforces table/key identifier syntax and byte
  bounds (including every reserved table name), validates canonical JSON and
  write conditions, and copies caller-owned values before persistence.
- [x] GET, PUT, UUIDv7 ETags, local historical reads, blind upsert, If-Match,
  create-only, close/reopen recovery, and OCC are implemented and tested.
- [x] The HTTP handler enforces table/key syntax, JSON/content-type/body
  limits, conditional headers, problem responses, and reserved routes.
- [x] `vbdbd --role=gateway --data-dir=... --listen=...` serves the standalone
  handler with bounded connections, active requests, server timeouts, and a
  hard-deadline graceful signal shutdown.
- [x] Metadata and storage roles, transactions, QUERY, admin, indexes, CDC,
  Raft, replication, and multi-process access remain explicit later work.

## Physical format

Keys are `pkg/codec` version-1 tuples. Head keys are
`("vbdb-head", table, key)`, history keys are
`("vbdb-version", table, key, sequence)`, version-index keys are
`("vbdb-version-index", uuid-bytes)`, and the sequence key is
`("vbdb-sequence")`. History keys sort by the unsigned big-endian sequence
component. Row values use a `VBDB` magic header, record format 1, record kind,
uint64 sequence, 16-byte UUIDv7, uint32 value length, canonical JSON bytes,
and a CRC32C checksum. Sequence records have the same magic/format/checksum
with a uint64 sequence; version-index values identify and checksum their
history key and UUID. Row and version-index decoders reject oversized encoded
values before CRC validation or payload copying. The four writes are one
synced Pebble batch, so a successful PUT does not become visible before the
WAL durability point.

Every immutable history record has one durable UUIDv7 index entry. The writer
checks that index before allocating a version, and open-time validation checks
both directions between index entries and history, so consecutive, ABA, and
restart collisions cannot create a second committed row state with an old
version. The storage layer enforces the same 63-byte lowercase table
identifier, reserved-name, and 1 KiB UTF-8 key bounds as the gateway (and
rejects slash-containing keys) even for direct callers. On Unix-like systems,
data directories are created and checked for owner-only `0700` permissions
before Pebble opens; Windows relies on its ACL model. The final cleaned path
is identity-checked before and after open; parent-directory replacement races
remain outside M2's trusted operator-configured path boundary.

Open performs an O(N) integrity scan over all user records: it checks typed
key components, nonzero sequence bounds and coverage, checksums, and that each
current head exactly equals the latest immutable history record for its table
and key. The temporary validation metadata is O(commits + live rows): it keeps
the global sequence set and only the latest history value per logical row, not
all historical value bytes. This startup cost is intentional in the
development-only milestone; it is not a distributed repair or fencing
protocol.

Tables are implicit in this milestone: the first PUT creates a table name by
using it in a physical key. There is no catalog, schema, or table DDL. A
single process must own a data directory; this is not a lock/fencing protocol.

## HTTP contract

Only `/{table}/{key}` with GET and PUT is served. Tables match
`[a-z][a-z0-9_-]{0,62}`, reserved names `_admin`, `_cdc`, and `transactions`
are unavailable, and the decoded key is one nonempty UTF-8 URL segment of at
most 1 KiB. PUT accepts a complete `application/json` document up to 1 MiB
and replaces the prior document. The same 1 MiB limit applies after canonical
JSON encoding, so HTML-sensitive strings that expand during canonicalization
are rejected before storage. Responses use the envelope described in the root
README. Errors use `application/problem+json` with stable `code`,
`title`, `status`, and `detail` fields, including `server_shutting_down` for
requests rejected by the graceful-shutdown admission guard. An
`X-Transaction-Id` is rejected with 501 rather than silently ignored.
