# Milestone 2 acceptance checklist

Milestone 2 is a development-only single-node database. The gateway is
runnable for HTTP GET/PUT/OCC over the owned native-Go engine, but it makes no
distributed, transactional, or production-cluster claim. This checklist
records the behavior and fault boundaries actually implemented in this
milestone; later distributed work remains outside its acceptance scope.

## Current commit: behavior proved

- [x] The gateway serves `GET /{table}/{key}` and `PUT /{table}/{key}` with
  bounded connections, active requests, request timeouts, and a hard-deadline
  graceful shutdown.
- [x] The HTTP layer enforces table/key syntax, reserved routes, JSON content
  type, request and canonical-value limits, conditional headers, ETags, and
  stable problem responses.
- [x] The storage adapter validates the same coordinates and byte limits for
  direct callers, rejects non-canonical JSON, copies caller-owned bytes, and
  evaluates blind-upsert, create-only, and If-Match under one writer lock.
- [x] Row history is immutable and keyed by logical table/key plus a local row
  sequence; a current head identifies the newest version. `GetAt` returns the
  newest history record at or before a requested local row sequence.
- [x] UUIDv7 is an opaque row version and strong HTTP ETag. A durable version
  index plus open-time checks reject UUID reuse across writes and restart.
- [x] Row, head, sequence, and version-index values use bounded, versioned
  binary records with CRC32C; malformed records are reported as corruption,
  not as missing rows.
- [x] The current adapter submits the row history, head, sequence, and
  version-index records as one synchronized atomic batch and has tests for
  close/reopen, corruption, concurrent OCC, and a real sync-failure fail-stop
  path.
- [x] Metadata/storage roles, transactions, QUERY, admin, indexes, CDC, Raft,
  replication, and multi-process access fail explicitly or remain outside the
  gateway contract.

These checks are exercised through the owned engine. Row startup logical
integrity validation still uses startup-only maps proportional to the persisted
row/history count; constant-memory row validation is deferred. Those maps are
rebuilt only during open and are not steady-state engine state.

## Owned-engine acceptance: implemented for M2

- [x] A native-Go `internal/engine` package exposes only bounded byte
  key/value operations, one serialized writer, concurrent pinned/read
  snapshots, and atomic write batches. It has no JSON, table, UUID, row, OCC,
  transaction, index, CDC, or Raft policy.
- [x] Every write batch is completely encoded and bounded before append. A
  versioned WAL frame contains bounded length, batch/physical-LSN metadata,
  complete operations, and a CRC32C. Short writes are handled explicitly.
- [x] The engine synchronizes the WAL before publishing the complete batch to
  the active mutable memtable. This durable-before-visible boundary makes all
  operations in one batch visible together and never exposes a batch whose
  durability point was not reached.
- [x] Physical engine LSN is documented and tested as a node-local recovery
  coordinate only. It is distinct from the storage-layer row sequence and
  UUIDv7; it is not a wall-clock or distributed timestamp.
- [x] Engine open uses a single owner-only directory rooted with Go's
  `os.Root`, rejects symlink/non-directory escapes, and acquires exclusive
  single-process ownership before serving. A second process is rejected.
- [x] Recovery validates all bounded record headers, versions, lengths,
  checksums, key/value limits, and ordering before serving. Only an incomplete
  suffix of the final active WAL segment may be truncated. A checksum failure,
  malformed complete frame, unsupported version, LSN gap, conflicting
  duplicate, or corruption anywhere else fails closed.
- [x] The first engine slice has an active mutable memtable and WAL with
  deterministic restart/replay tests. It remains explicitly development-only
  and makes no distributed or production-cluster storage claim.
- [x] The two-level LSM has overlapping immutable L0 SSTs and
  non-overlapping range-partitioned L1 SSTs. SST blocks/metadata and the
  manifest are versioned and CRC32C checked, and flush/compaction publication
  is durable before visibility.
- [x] SST/manifest publication follows write-temp, file-sync, rename,
  directory-sync, manifest-publish, then visibility. Obsolete files are
  deleted only after the superseding manifest is durable and all snapshot and
  iterator/read pins are released. Backup and restore pins are future APIs.

M2 development-only acceptance is complete for this single-node scope. It
must not be described as a distributed or production-cluster storage system.
Background compaction, group commit, block cache, metrics, backups/PITR, Raft,
and distributed MVCC timestamps are later milestones.

## Layer and timestamp boundaries

The raw engine stores ordered bytes and owns physical LSN/WAL/SST/manifest
durability. The storage/MVCC adapter owns canonical tuple namespaces,
immutable row history, current heads, local row sequences, UUID-version
uniqueness, and OCC. A raw snapshot is not an MVCC transaction and a local
physical LSN is not a row visibility timestamp.

M2 uses a local row sequence for `GetAt`; the sequence is part of the row
history key and is advanced only in the same durable row batch. UUIDv7 is only
an opaque row version/ETag. Later replicated storage will use the Raft apply
index as the authoritative MVCC timestamp, encoded after each logical key in
descending order. Transaction records, global indexes, deduplication, Raft
metadata, and cross-range atomicity sit above the raw engine and are not
implied by one local batch.

Later backup/PITR must publish an immutable snapshot manifest and retain the
Raft journal needed to replay committed logical history after that snapshot.
The raw-engine manifest, local LSN, or row-history scan alone is not a PITR
implementation.

## M2 row and key format

The current row adapter uses version-1 `pkg/codec` tuples. Head keys are
`("vbdb-head", table, key)`, history keys are
`("vbdb-version", table, key, row-sequence)`, version-index keys are
`("vbdb-version-index", uuid-bytes)`, and the row-sequence key is
`("vbdb-sequence")`. History keys sort by their unsigned big-endian sequence
component. These are storage-layer records; the owned raw engine treats them
as opaque bounded bytes.

Row values use a `VBDB` magic header, record format 1, record kind, uint64 row
sequence, 16-byte UUIDv7, uint32 value length, canonical JSON bytes, and a
CRC32C checksum. Sequence records use the same magic/format/checksum with a
uint64 row sequence. Version-index values identify and checksum their history
key and UUID. Decoders reject oversized encoded values before CRC validation
or payload copying. A successful row batch makes history, head, index, and
sequence durable together; a missing or corrupt member is not an absent row.

Every immutable history record has one durable UUIDv7 index entry. Write-time
index checks and open-time checks in both directions reject consecutive, ABA,
or restart collisions. Current-head bytes must exactly match the latest
history record for the logical table/key. Tables are implicit physical
namespaces in M2; there is no catalog, schema, or DDL.

## Recovery, ownership, and explicit v1 exclusions

The owned engine opens only beneath one owner-only directory held by one
process. All child paths are resolved through `os.Root`; configured parent
directories are outside the engine trust boundary. Directory and lock setup
fails closed on symlink, mode, identity, or ownership uncertainty.

Open validates the checksummed manifest and every referenced SST, then replays
WAL frames beyond the manifest's flushed physical LSN. Only an incomplete
final active-WAL suffix is truncatable. Complete-frame corruption, malformed
boundaries, gaps, conflicting duplicates, unsupported versions, invalid
bounded records, or missing referenced files are terminal. No salvage,
best-effort repair, or online migration is provided in v1.

The v1 owned format deliberately excludes compression, levels above L1,
mmap/direct I/O, range tombstones, remote SST reads, and engine-level
encryption. Flush and compaction are synchronous; background compaction,
group commit, block caching, metrics, backups/PITR, Raft, and distributed MVCC
timestamps are deferred. Deployments may use volume encryption; the engine
does not claim per-record or per-file encryption.

## Required test and fault gates

- [x] Unit tests cover versioned frame/record codecs, canonical bounds,
  CRC32C, short writes, partial final-frame truncation, and representative
  malformed-complete-frame rejection. The test suite does not claim exhaustive
  enumeration of every malformed byte pattern.
- [x] Engine integration tests cover one serialized writer with concurrent
  snapshots, atomic multi-operation batches, durable-before-visible ordering,
  restart replay, LSN progression, and snapshot pin release.
- [x] Filesystem tests cover descriptor-rooted ownership, symlink rejection,
  owner-only directory policy, exclusive second-process rejection,
  manifest/SST publication ordering, and safe obsolete-file retention while a
  snapshot is pinned. A dedicated traversal-specific test remains useful
  hardening.
- [x] Fault-injection tests cover targeted WAL write/sync failures, partial
  and complete writes, SST/manifest/CURRENT file sync failures, SST and root/
  SST-directory sync failures, torn tails, checksummed frame/manifest/SST
  corruption, checksummed LSN gaps and conflicting duplicates, missing
  manifest-referenced SSTs, and simulated disk-full writes at WAL/SST/manifest
  boundaries. Every uncertain durability or recovery result terminates the
  instance; tests accept only a complete durable batch or the prior state.
- [x] Row-layer tests retain the current GET/PUT/OCC, UUID uniqueness,
  canonical JSON, history/current-head, bounds, corruption, and close/reopen
  coverage against the owned engine adapter.
- [x] The normal scoped gates pass through `make check`: formatting and
  formatting self-tests, vet, unit tests, race tests, public safety and public
  safety self-tests, diff self-tests, and the local markdown-oriented diff
  check.

These checked boxes close the implemented M2 engine and row/HTTP acceptance.
They do not expand M2 into transactions, QUERY, indexes, CDC, backups/PITR,
Raft, HA, or autoscaling.
