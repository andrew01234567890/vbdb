# Milestone 3 acceptance checklist

- [x] New branch starts from the accepted M2 owned-engine tip; old M3/M4
  branches are reference-only and untouched.
- [x] Raft commands/results are deterministic, canonical, versioned, and
  checksummed; proposer operation and row UUIDv7 values survive retries.
- [x] HTTP, storage, and Raft use the shared coordinate validator.
- [x] Operation IDs have durable dedupe/results and explicit conflict and
  ambiguous-retry outcomes.
- [x] Raft apply index is the logical row-history coordinate; UUIDv7 is not a
  timestamp or sequence.
- [x] Ready processing persists Raft state, then logical apply, then sends
  messages, then advances; fatal storage uncertainty stops the replica.
- [x] Proposal, Ready, logical batch, retained result, snapshot chunk, and
  virtual transport resources have finite bounds.
- [x] Snapshots use bounded chunks and generation metadata; incomplete staged
  generations are not visible after restart.
- [x] Obsolete Pebble directories are explicitly rejected.
- [x] Membership helpers admit one validated non-joint ConfChangeV2 at a time;
  full joint membership orchestration is excluded.
- [x] Deterministic tests cover RF3 apply, reordered delivery, partition/heal,
  restart, dedupe, snapshot round-trip, and obsolete-format rejection.

## Explicit exclusions

M3 does not implement production RPC/flow control, routing or follower-read
fences, transactions, indexes, CDC, backup/PITR, online resharding, or
operator/autoscaling policy. Those features require later milestones.
