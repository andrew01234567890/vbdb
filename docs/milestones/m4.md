# Milestone 4 acceptance checklist

M4 is a deterministic in-process proof built on the accepted M3 RF3 Raft
shard. It does not claim production RPC, independent child Raft groups, or a
crash-resumable split coordinator.

## Proven in this stack

- [x] Complete range descriptors and canonical catalog generations fence span,
  immutable ID, generation, owner epoch, group, voters, and phase.
- [x] Catalog images persist through the owned engine before publication;
  retired source tombstones and exact RF3 membership survive restart checks.
- [x] Follower ReadIndex contexts are bounded, boot-nonce fenced, correlated
  from copied ReadStates, and released on cancellation, close, fatal, or
  failure. Reads wait for durable logical apply and recheck the full route.
- [x] Snapshot chunks are bounded, reorderable, and exact-duplicate tolerant;
  malformed, missing, conflicting, and checksum-invalid input is rejected
  before child projection mutation.
- [x] Source barriers use logical applied sequence and retain bounded ordered
  deltas carrying complete source identity and command/result identity.
- [x] Catch-up validates a copied left/right projection and swaps it only
  after contiguous deltas succeed; late failure leaves the live projection
  unchanged.
- [x] Target proof checks adjacent child spans, RF3 membership, `ConfState`,
  checksum/digest evidence, and quorum before cutover.
- [x] One cutover publishes both serving children and the retired source in a
  single catalog replacement; stale source routes cannot mutate state.
- [x] Retry identity freezes operation ID, canonical command bytes, and the
  candidate UUIDv7 version; equal retries are idempotent and conflicts fail
  without mutation.
- [x] Complete-generation recovery markers and catalog membership checks fail
  closed on incomplete or foreign state.
- [x] Deterministic tests cover delay/drop/duplicate/reorder, secondary
  failure/fallback, quorum loss, response-loss identity, and retained-state
  bounds using synthetic RF3-shaped state.

## Deferred explicitly

Production authenticated RPC/flow control, independent child Raft groups and
cross-process failover, crash-safe recovery of an in-flight coordinator,
concurrent merge/rebalance/autoscaling policy, global indexes, transactions,
CDC, backup/PITR, operator reconciliation, and Jepsen/Elle histories remain
future work. No M4 test or API treats the deterministic harness as proof of
those properties.

## Gates

The per-slice focused tests, vet, ordinary package tests, diff checks, and
public-safety scans are run locally. The existing M3 RF3 status test is timing
flaky under the full race matrix; its exact targeted race test passes at
`-count=3`. This caveat is retained honestly rather than hidden by changing
the M3 implementation in an M4 acceptance branch.
